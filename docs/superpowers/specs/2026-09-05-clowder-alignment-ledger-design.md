## 背景与目标

meowbase 的愿景是 95% 参考 [clowder-ai](https://github.com/zts212653/clowder-ai)（MIT）实现，作为简历/面试用途的作品集项目继续演进。本设计覆盖的**只有第一刀**：产出对齐总账。后续每条缺口的实现各自走仓库现有流程（`docs/features/` 薄设计 → 一刀 → 六道闸），不在本设计范围内。

验收标准（已与用户对齐）：**功能清单对齐**——「95%」= 策展核心清单上 95% 的条目落地，总账是唯一权威计分处。排序原则：有面试节点，**叙事优先**。

## 设计

### 1. 交付物与位置

新增 **`docs/ALIGNMENT.md`（clowder 对齐总账）**，登记进 `docs/README.md` 文档地图。任何时刻打开它能回答三件事：分子分母各是多少、每条什么状态、下一条建议补什么。

### 2. 策展标准（分母）

从 clowder 309 条 F 文档中筛两类进分母：

- **映射到愿景七件事**：路由 / 线程 / 身份 / 记忆 / 技能 / 审批 / 审计（如 F002 A2A、F046 防漂移协议、F013 审计、F008 token 可观测、F038 技能发现、F186 图书馆记忆等）
- **README 已点名的形态缺口**：邮箱 / SOP / MCP、review 回流（F140），以及 `docs/PROGRESS.md`「下一刀候选」里已对过 clowder 的条目

**明确排除**（记一行「有意不做 + 一句话理由」，不计入分母）：游戏类（F090/F101/F107/F119/F170 等）、语音类（F020/F034/F066/F092/F103/F111/F112/F124/F176 等）、硬件四肢（F126/F270/F285）、IM 网关（F088/F132/F134/F137/F151 等）、桌面发布管线（F179/F273）、视频管线（F138/F205）、陪伴/世界引擎（F093/F255/F258 等）。

「有意不做」剔除出分母但**必须写理由**——剔除理由本身是面试素材，保证 95% 是诚实数字。

### 3. 总账格式（每条四栏）

| 栏 | 内容 |
|---|---|
| 状态 | `已对齐` / `部分对齐（差什么）` / `缺失` / `有意不做` |
| clowder 出处 | F 号 + GitHub 链接（只拿语义和踩坑，不抄源码） |
| meowbase 证据 | 已对齐的链接到实现/功能稿；缺失的空着 |
| 面试钩子 | 一句话：这条能讲出什么判断（排序依据之一） |

顶部写当前对齐率。**对齐率 = 已对齐条目数 / 分母条目数**；`部分对齐` 不算落地（差什么写在状态栏，补完才翻成 `已对齐`），`有意不做` 已剔除出分母。此页是对账页，写进度数字是它存在的意义，不受 PROGRESS「不写数字」规矩约束；但每条状态必须随对应刀**同轮更新**（与文档同轮更新约定一致）。

### 4. 排序原则

`面试叙事价值 × 工程依赖 × 成本（不花钱优先）`。已知高价值候选：

- 邮箱 / SOP / MCP 三形态（README 明写的差距）
- F140 review 回流 / CI 追踪（PROGRESS 候选第一条）
- 预算闸（「平台会不会拒绝」那条道从「中」补厚的关键，PROGRESS 候选）
- 技能有没有用的度量（厚薄表唯一「薄」的道）

总账给建议顺序；每条开工前仍先写薄设计、等人点头。

### 5. 这一刀的执行

1. 并行子 agent 精读 clowder 核心 F 文档与架构文档（只读公开语义）
2. 产出 `docs/ALIGNMENT.md` + 登记 `docs/README.md`
3. 六道闸照跑（纯文档刀，预期无影响；`pnpm e2e:web` 必须在沙箱外跑）
4. 一次提交；`docs/PROGRESS.md` 记增量；厚薄表不动（本刀不改任何一条道的实质）

### 6. 明确不做

- 不搬 clowder 源码（只拿语义和踩坑，仓库既有约定）
- 不改任何功能代码
- 不定后续每条缺口的实现方案（各自薄设计的事）
- 不给「95%」定截止日期
