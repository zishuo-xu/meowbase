# 平台自己花的钱也进账，探测不许假装成功

一篇只写**一个**可验收的特性。做完再开下一篇。

- 状态:`已落地`
- 对照 clowder:我们查过的公开范围里(README / SOP / TIPS / public-lessons / architecture / features / issues)**没有「模型连通性探测」这一刀**,也没有「平台自己的花费」这种账目。能靠的只有原则句:**LL-039**「gate 里推进 cursor 等于还没干活就划卡——execute 失败后事件丢失」,和 **LL-029**「不要只读 `.md` 就下结论——`.md` 是索引,git 才是真相;『完成』必须有 commit + PR merged」。两条同一个意思:**没真干成的事不许显示成干成了**。
- 靠拢:靠那条原则,不靠规格。本刀是喵窝自己的薄片——他们没有这个动作,所以没有更近的东西可靠。

## 门（各一句）

- **功能**：模型名空着不再发起真实调用(400 + 字段提示);探测真的跑了就把这次的 token 和花费显示在探测结果里
- **价值**：人点「验证」之后看到的「已连通」指的是**他填的那个模型**;账本回答「猫花了多少」,探测花费当场看见
- **愿景**：仍是邮差。平台不替人决定要不要花这笔钱,但花了就得如实报账
- **落点**：`providers/verify-model.ts` 返回值 + `http/server.ts` 那个路由的校验 + `TeamHub` 表单反馈和账本那一格口径。不新开第二心脏,也不改 `loadUsage`

## 为什么

**「已连通 · pong」现在可能是个谎,链路五节。** 新模型表单的 `newBins` 初值就是 `['opencode']`、`newModel` 初值是空串;`probeSpec` 在模型名为空时**省略** model 参数;于是 `opencode` 用**它自己的默认模型**跑一趟真推理;回来 UI 报「已连通 · pong」。人以为自己要加的模型验通了,其实验的是 CLI 的默认模型。这正是 LL-039 那个形状:动作没真发生在目标上,卡却划了。

**账本有一条结构性的洞,不是漏记一行。** `verifyModelConnection` 里 `adapter.runTurn()` 是真调用,而 `AgentTurnOutput` **本来就带 `usage`**——是这个函数自己把它丢掉了,只返回 `{ok, stage, latencyMs, preview}`。另一边 `loadUsage` 的口径是「遍历线程 → 汇总助手消息的 usage」。探测不属于任何线程、任何猫,所以它**永远进不了账**,不管跑多少次。

`AGENTS.md` 里「只算跑完的助手消息」这句字面上是准的,但账本这个功能要回答的问题是**「我花了多少」**。现在有一条路绕过它,那这个数就是错的——而「可证明性」是这个项目最厚、对外讲得最多的一条道。用户测试里那次误触发的探测,花了多少**查不出来**,恰恰因为这个洞。

## 怎么做

1. **模型名空着就不许探测**。路由现在只校验 `bin` 非空。加一条:模型名为空则 400(带字段名),**不发起任何调用**。理由不是省钱,是省一个谎——省略 model 参数会静默换成 CLI 的默认模型。

2. **探测把用量带回来**。`VerifyModelResult` 加 `usage?: TokenUsage`,把 `output.usage` 透出来(数据已经在手上)。gemini 不报成本,那格按现有约定显示「无成本数据」,**不要估、不要写 `$0`**。

 **探测失败也要显示用量**(只要 CLI 报了)。失败的调用照样可能烧了 token——模型跑完了、解析失败,钱不会因为结果失败而退回来。这和账本「失败的助手消息不算钱」不冲突:那是计费口径,这是如实显示。

3. **账本的口径写死,不撑大**。考察过七个 store,没有一个能直接放这笔账目:`messages` 要 `threadId` 还要假装成某只猫的助手消息;`audit` 是 best-effort、`try/catch` 吞失败、还有 5000 条全局封顶,当账本源会丢账,且和 [quota-board.md](quota-board.md)「真相取自消息不取自审计」直接打架;`AuditRow.threadId` 又是必填,走审计还得改核心类型。**结论是都不选**:探测是人手点的、同步的、一次三秒,这个项目一辈子几十次、每次成本在分以下,为它开第八个 store 或改核心类型,是为几分钱铺基础设施——正是 LL-020 那条判据(脚手架远超问题就先问方向)。

 所以:**账本回答的是「猫花了多少」**,这个定义写进 UI 那一格和 `AGENTS.md`,不让人以为总数包含一切;探测的花费在**花的那一刻**就摆在探测结果里(第 2 步)。两个问题两个答案,都不含糊——「金额无法确认」不是靠事后能查修掉的,是靠花的时候你就看见了。

 **什么时候该加厚**(明确触发条件,不是「以后再说」):平台出现**第二条**花钱路径时(例如自动健康检查定时探测)。那时候花费会累积、会脱离人的视线,才值得有个家。

4. **表单不再静默失败**。「加入目录」现在遇到空模型名或没勾 CLI 就 `return`,什么都不显示。改成字段级提示。同一处顺手做,不单开一刀。

5. **验收**。模型名留空点「验证新模型」→ 400、有字段提示、**没有真实调用**(拦在发起之前,不是发起之后才不显示成功);填一个真模型名 → 结果里带 token 和花费;账本那一格写明只算猫的。真实调用花钱,所以这一步归人跑,不进 CI。

6. **自动化那一半**。校验和透传都是纯逻辑,单测覆盖:空模型名 400 且**没调用适配器**(用 spy 断言零调用)、`usage` 透传、失败也透传。`loadUsage` 不改。记分板**不加行**——这一刀量的不是「猫的坏毛病」,不属于那张表。

## 不做（本篇）

- **不做预算闸**。账本仍然只能看不能拦;花超了停手是另一刀。
- **不做窄屏适配**。手机那条承诺这一轮已经在 `README.md` 收回成「不建议」,布局单独一刀。
- **不动那四条 API 输入校验**(`primaryAgentId` 不校验、非字符串 `title` 500、给不存在的线程发消息 500、取消 409)。它们是同一类「用户错误被当服务器故障」,合成另一薄刀。
