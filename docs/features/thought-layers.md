# 思考与计划分层

一篇只写**一个**可验收的特性。写完就做这一篇,做完再开下一篇。不要在这里预写路线图。

开篇先想:同一问题他们公开怎么设计,这一篇能靠多近。能靠就靠;本篇没更近,写清差在哪、为什么先薄。不读、不抄源码。

- 状态:`已落地`
- 对照 clowder:F045 —— 消息分层可观测,thinking / plan 不是同一坨正文。
- 靠拢:拿「计划从思考里拆出来,气泡各占一块」。差在独立遥测通道和 NDJSON 计划事件:本篇只拆字段、不新开 WS 类型。

## 门（各一句）

- **功能**：助手消息可带 `plan`。思考里出现「计划:」就拆开;气泡先计划后思考,默认都收着,不混进对用户说的话。
- **价值**：面试能讲「内心独白和步骤清单不是同一层」;人点开计划就能看见它打算怎么干。
- **愿景**：仍是邮差。信封里分夹层,不替猫改步骤。
- **落点**：`splitThoughtLayers`;跳完成写 `plan`;前端 `PlanBlock`。

## 为什么

思考已经能流、能落库、能点开。对照他们:还差计划层。现在计划和胡思乱想挤在「思考过程」里,演示时像一坨灰字。不做成 X:把正文当计划解析,把对用户说的话拆没。

只从 `thinking` 拆,不碰 `content`。没有「计划:」标题就整段仍是思考。

## 怎么做

1. `splitThoughtLayers(thinking)`:按行首 `计划:` / `Plan:` 切开,标题后到下一个空段或全文结束是 plan,其余是 thinking。
2. 跳完成 `patch` 时同时写 `plan` 和拆完的 `thinking`。流式前端对累积 thinking 做同一刀,不新开 WS。
3. 气泡:`plan` 有则显示「计划」,点开才见正文;思考块照旧。
4. 验收:思考是「先看目录\n计划:\n1. 写 add.ts」→ 计划块有「1. 写 add.ts」,思考块没有「计划:」;正文仍是对用户说的话。

## 不做（本篇）

- 独立 `plan` WS 事件 / 遥测通道
- 从助手正文抠计划
- 让猫按固定 JSON 交计划
