# 记忆按仓库划界,注入带出处

- 状态:`已落地`
- 对照 clowder:他们**按项目一份 `evidence.sqlite`**(`SETUP.md`「Long-Term Memory」),同一项目里跨线程能搜到**是故意的**(F102 的 `scope = docs | threads | sessions | all` 只是检索切面,不是隔离边界);Collection 之间「知识不自动互通」,跨域结果必须标 `collectionId / sensitivity / authority / reviewStatus`(F186 KD-4、AC-A5)。注入侧要求带走回原文的路和时效:`passageId` + speaker + timestamp,**不返回「摘要结论」**(F209 AC-A4、KD-2);渲染 `[match:… · authority:… · updated:…]`,**`updated:unknown` 不许省略**(F263 AC-A3);他们自查 9 个注入面有 4 个断链(F263 R7)。LL-092:没出处没立场的摘要被高权重注入,会被当成「我认识这个用户」。
- 靠拢:**边界按仓库、注入带出处这两条直接靠**,他们写死了。三处必须我们自己定,不许假装他们写过:(1)**没绑仓的空沙箱线程**归谁,他们没有这张图;(2)**确认时间**我们压根没存,得新加字段,老数据只能落「未记」——正好照他们 `unknown` 那条纪律办;(3)**继续用 push 是刻意偏离** —— 他们主路径是猫自己 `search_evidence`(pull),自动灌进系统提示词在他们纲领里被判成「context DDoS」(memory-philosophy M5、反模式 G1),而「记忆是数据不是指令」明确禁止把记忆当规则拼进 system prompt(F186 KD-6、M2/M12)。本刀**不改召回模型**,只给现有那条 push 加边界和出处;pull 留给以后另开一篇。

## 门(各一句)

- **功能**:人在不同项目里用 `#learn` 攒下来的东西不再互相串台,而且猫拿到某条记忆时能看出它从哪来、什么时候确认的。
- **价值**:人不用担心「换个项目开线程会不会被上个项目的约定带跑」,也不用猜猫到底吃进去了什么。
- **愿景**:仍是邮差 —— 平台不判断记忆对不对,只负责**送对范围**并且**标清出处**。
- **落点**:`shared/evidence-recall.ts`(候选范围 + 纯函数)、`shared/system-prompt.ts`(注入行格式)、`router/execute-turn.ts`(召回那三行)、`GET /api/evidence`(让界面问得出「猫能看见哪些」)。不新开心脏。

## 为什么

现在有三个毛病,今天都验过:

**召回不分范围。** `execute-turn.ts` 调的是 `context.stores.evidence.list()`,**没传 threadId** —— store 明明支持过滤。所以任何线程确认过的东西都能被灌进任何线程,包括绑着**不同仓库**的线程。

**界面和猫看到的不是同一批。** 前端拉的是 `/api/evidence?threadId=${threadId}`,**按线程过滤**;召回给猫的是全局。所以侧栏告诉你「这条线程的记忆是这几条」,猫实际吃到的是另一批,而人看不出差别。对一个把可证明性当卖点的项目,这条比串台本身更难看。

**注入不带出处。** 格式是 `- [kind] 标题: 内容`,没有 id、没有来源、没有时间。猫无法判断这条「团队记忆」是本项目的还是别的项目的、是上周的还是三个月前的 —— 正是 LL-092 那条教训的形状。

眼下伤害还没发生,得说句公道话:现网 120 条已确认证据**全是单测留下的** `x` / `y`(踩坑 11 早写了测试数据会留在 Redis),含中文 0 条,而分词器要求中文 ≥2 字、英文 ≥2 字符,真实提问匹配不上它们。**所以这是缺陷已存在、还没咬人。**

但风险刚被上一刀推高:`remote-opt-in.md` 让「在本地跑自己的项目」变顺手,**多项目使用会变自然** —— 那正是跨项目记忆串台从「理论上」变成「会发生」的条件。

## 怎么做

1. **范围规则做成 shared 纯函数**,一处定义、召回和界面都用它:
   - 当前线程**绑了仓** → 候选是「绑同一个仓的线程」产出的已确认证据。同仓跨线程共享,这是照他们的设计,不禁。
   - 当前线程**没绑仓**(空沙箱)→ 候选只有**本线程自己**的。他们没有这张图,这句是我们补的:空沙箱是一次性实验,没有「项目」可共享,缺省落严那侧。
   - 比对仓库路径用 canonical realpath(踩坑 32:macOS 上 `/var` 和 `/private/var` 是同一个地方)。

2. **不给 `EvidenceEntry` 加仓库字段。** 它已经有 `threadId`,召回时拉一次线程表(现在 22 条,一次 `list()`)建 `threadId → repoPath` 映射即可。加字段要迁移老数据,而老数据压根没有仓库信息,只会多一列谎。

3. **加 `confirmedAt?: string`**,在 `confirm()` 里落时间。现在 `confirm()` 只翻 `status`、**一个时间都不记**,`createdAt` 是草稿产出时间不是确认时间。老数据没有这个字段,注入时落成「确认时间未记」——**不许拿 `createdAt` 顶替**,那是编。

4. **注入行带出处**:`- [kind] 标题(ev_xxx · 来自 <仓库目录名 或 线程标题> · 确认于 <日期|未记>): 内容`。同时把那段的抬头从光秃秃的「团队记忆」改成点明**这是检索到的历史记录、不是本轮指令** —— 对着他们「记忆是数据不是指令」那条。

5. **让界面问得出「猫能看见哪些」**:`GET /api/evidence` 支持按召回范围查(同一个纯函数),侧栏 rail 改用它。人看到的和猫吃到的必须是同一批,这是这一刀的主要交付物之一,不是附赠。

6. **记分板加一行**「别的项目的记忆被灌进来」,期望 1。两个仓、两条线程,在 A 仓线程确认一条证据,在 B 仓线程发一句带「之前我们约定」的话,断言 A 的内容**没有**出现在 B 那跳的提示词里。这是 `记忆` 这条道上的第一行,以前一行都没有。

**验收**:
- 仓 A 确认的条,在绑仓 B 的线程里问「之前我们约定…」不再出现;绑同一个仓的另一条线程里**仍然**出现(共享是设计,不是漏)。
- 空沙箱线程只召回自己的。
- 猫拿到的那行能看出 id、来源、确认时间;老证据显示「未记」而不是假装有时间。
- 侧栏 rail 显示的条目和猫这一跳能看见的完全一致。

## 不做(本篇)

- **不做猫主动 pull**(他们的 `search_evidence` 那套)。召回模型换代是另一刀,本篇只给现有 push 加边界和出处。
- **不做向量 / 语义召回、不做相关性阈值、不做时间衰减。** 关键词打分和取前 3 原样不动。
- **不做记忆管理**(删除、编辑、跨项目显式借用、Feed 审阅)。所以现网那 120 条单测垃圾这一刀清不掉 —— 接口仍然只有 `GET`,记忆仍是只进不出。它们无害(匹配不上),但「人管不了记忆池」这个结构性问题留着,以后另开篇。
- **不改 `#learn` / `#confirm` 语法和状态机。**
