# 顶栏点开就能看见排队

一篇只写**一个**可验收的特性。写完就做这一刀，做完再开下一篇。不要在这里预写路线图。

开篇先想：同一问题他们公开怎么设计，这一刀能靠多近。能靠就靠；本刀没更近，写清差在哪、为什么先薄。不读、不抄源码。

- 状态:`已落地`
- 对照 clowder:公开 QueuePanel —— 线程忙时可见 queued / processing，agent 条目单独渲染。
- 靠拢:拿「人能看见后面排着什么」。不搬拖拽、steer 插队、优先级。落在现有顶栏下面一张小纸条，不新开侧栏。

## 门（各一句）

- **功能**：顶栏「后面还有 N 棒 / 还有 N 句在等」可点开，列出交棒队（谁交给谁、任务一句）和人话队（正文一句）。
- **价值**：面试演示不用猜 Redis 里有没有第二棒；人看得见自己插的那句还在不在。
- **愿景**：仍是邮差。面板只展示信封，不改路由。
- **落点**：`QueuePanel` + 顶栏球权行变成按钮。数据已在 `GET /api/threads` 的 `pendingQueue` / `inboundQueue`。

## 为什么

交棒排队和人插话排队都落地了，顶栏却只跟数量。对照他们，邮箱要**看得见**才算演示完成。不做成 X：简历讲「忙就排队」时屏幕上只有一句文案，面试官问「排的是什么」答不上来。

## 怎么做

1. `ThreadDto` 的 hop 带上 `task`（列表接口本来就有，前端类型漏了）。
2. `QueuePanel`：空则不渲染；有货时两段——「下一棒」「人说的」。文案短、一条一行。
3. 顶栏球权行在有货时是按钮，点开/再点收起。没有排队时仍是纯文字。
4. 验收：pendingQueue 一条 + inboundQueue 一条 → 点开看得到「墨墨 → 闪闪」和人话正文。

## 不做（本篇）

- 拖拽改序、删队中某一棒(插队见 [queue-steer.md](queue-steer.md))
- 跨线程总览
