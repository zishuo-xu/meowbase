# 续跑的产出即时推到前端：sync 事件

一篇只写**一个**可验收的特性。写完就做这一刀，做完再开下一篇。不要在这里预写路线图。

开篇先想：同一问题他们公开怎么设计，这一刀能靠多近。能靠就靠；本刀没更近，写清差在哪、为什么先薄。不读、不抄源码。

- 状态:`设计中`
- 对照 clowder:公开是异步 A2A + 富消息卡片 + 飞书投递 —— 服务端产出主动送到人眼前,人不用回去刷新问一遍。
- 靠拢:靠「服务端产出主动送达」这条。差在:不开推送通道、不做富消息协议,只在现有 WebSocket 上加一个最薄的 `sync` 事件。

## 门（各一句）

- **功能**：交棒续跑产出的接力条、球权、审批卡、侧栏「待确认」,人不点第二下就出现
- **价值**：人不用怀疑「是不是卡住了」,也不用手动点一下线程才看见结论
- **愿景**：邮差把信送到门口,不让人自己跑去邮局窗口问有没有信
- **落点**：`buildServer` 里给注入的 store 包一层广播装饰器 + WS 多一种 `sync` 事件 + web 收到就重拉。`executeTurn` 和 `turn/` 一行不改

## 为什么

WS 现在只推 `increment` / `activity` / `start` / `thinking`（`packages/api/src/http/server.ts` 468–477）。**没有一种事件表示「有系统消息或审批卡产生了」**。而 `followPendingChain` 是 POST 返回之后才在后台跑的,所以它产出的接力条、球权提示、审批卡全落在 HTTP 响应之外;前端只在 `send()` 返回那一刻拉过一次消息,之后没人告诉它该再拉。侧栏角标同理 —— `refreshThreads()` 在卡片存在之前就跑完了。

真机实测（真实模型,绑真实仓库）:闪闪写完「结论:通过」、卡片已在 Redis,界面仍停在「球在闪闪手上 / 思考中…」,重新点一下线程才刷出卡片和「球在人手里」。而 `docs/DEMO.md` 写「不必再发继续」,`AGENTS.md` 写「审查官写出通过 → 顶栏球回人手里;不必等审批卡刷出来」。两句在服务端都是真的,在人眼前都是假的。

为什么不给每类系统消息各发一种事件:那要在二十来处 `append` 里挑着埋点,还得让前端认服务端的消息分类,两边一定漂移（结构化系统消息是以后另一刀）。发一个不带载荷的 `sync`,服务端只说「这条线程变了」,前端自己去拉 —— 语义没有可漂移的地方,而且一次修好卡片、球权、角标三件事。

## 怎么做

1. WS 增加事件 `{ type: 'sync', threadId }`,不带载荷。
2. `buildServer` 里把注入的 `messages` / `approvals` / `threads` 各包一层广播装饰器:`append` / `patch` / 建卡 / `setReviewComment` / `approve` / `reject` / `markApplied` / `setPendingHop` / `rename` **成功之后**发 `sync`。turn 路径和 REST 路径共用同一批实例,包一次两边都覆盖。
3. 流式增量**不发** `sync`（增量走 `increment`,不落库）,否则刷屏。
4. web 的 `use-thread-stream.ts` 认 `sync`;`page.tsx` 收到就重拉 messages + approvals + threads,客户端合并去抖约 150ms,避免一轮里连发多次各拉一次。
5. 搭车两个小的:用户气泡保留换行（`white-space: pre-wrap`）,让行首 `@` 看起来就是行首,不再像句中 @;关 socket 前先看连接状态,去掉切线程时那条 `WebSocket is closed before the connection is established`。
6. 验收：绑仓线程发「…\n@墨墨」后**全程不碰鼠标** —— 接力条、闪闪回复、「球在人手里」、审批卡、侧栏「待确认」都自己出现;点批准后「已落地」也自己出现。

## 不做（本篇）

- 不做结构化系统消息（`systemKind`）和球权状态字段
- 不推消息体增量,`sync` 只说「变了」,前端自己拉
- 不做浏览器通知 / 飞书 / 邮箱投递
- 不改 A2A、审查、审批、持球任何语义

## 面试能讲

- **30 秒**：服务端在 HTTP 响应之外继续干活,就必须有办法告诉人;不然文档里那句「不必再发继续」在人眼里就是卡住了。
- **追问「为什么不直接推消息体」**：推载荷要前端认服务端的消息分类,两边会漂移;先推「变了」,一次修好卡片、球权、角标。
- **追问「装饰器为什么加在 `buildServer`」**：turn 路径和 REST 路径共用同一批 store 实例,包一次两边都覆盖,心脏不用改。
- **踩坑**：流式增量不能发 `sync`（会刷屏）;关 socket 要先判连接状态。
