# 异步交棒（往 clowder 靠的第一刀）

- 状态:`设计中`（未实现。先写设计，实现前再对照一次他们公开 A2A / 队列文档）
- 对照 clowder:公开 A2A 是**异步**消息；后来有统一消息队列、hold_ball、MCP `targetCats`。我们只评估「人能离开、球还在谁手上」这一条语义。
- 相关:已落地的同步接力 [a2a.md](a2a.md)、[docs/A2A.md](../A2A.md)

## 功能

墨墨交完闪闪后，**本轮可以先结束**。球标在闪闪手上。线程空闲或人点「继续」时，平台再唤闪闪拆同一份交接包。人不必盯着一条 `executeTurn` 跑完整串。

## 价值

- 对人：发完可以去干别的；多条线程能交错推进。
- 对面试：能讲清「同步接力 vs 异步投递」的取舍，而不是只会说「我们没做邮箱」。

## 愿景

仍是邮差。人随时能看见球在谁手上。不把派球权交给 MCP 工具，第一刀也不做「占球等到 CI」。

## 架构落点

**必须挂在现有心脏后面，不新开第二路由器。**

建议形状（实现时再拆任务）：

1. `executeTurn` 跑完当前这一跳后，若解析到行首 `@下一只`，把交接包写成一条 **pending hop**（线程内、可序列化），本轮返回。
2. 顶栏 / 球权：持球者 = pending 的目标猫（或 `@人`）。
3. 下一拍入口仍是 `executeTurn`：用户再发消息、或「继续」空指令、或线程空闲调度 —— 取出 pending，当第一棒那样 `runTurn`。
4. 存储加端口方法即可（`PendingHopStore` 或挂在 ThreadStore），业务不直接碰 Redis。

对不上的做法：独立 mailbox 进程、跨线程私信、`hold_ball` MCP、InvocationQueue 当主入口。

## 为什么这样设计

根因：同步接力把「闪闪要跑两分钟」绑在「人这条 HTTP/WS 还没结束」上。人一离开或想并行第二条线程，就被堵住。这是他们公开「异步 A2A」真正多出来的能力。

| # | 决策 | 理由 |
|---|---|---|
| D1 | 第一刀只做「延后下一跳」，不做通用邮箱 | 邮箱是操作系统；我们要的是人能离开 |
| D2 | 交接包格式不变 | UI 接力条、`formatA2AHandoffPrompt` 继续是单一真相 |
| D3 | 调度仍进 `executeTurn` | 命令、审批、记忆、防环不用写第二遍 |
| D4 | 暂不做 hold_ball / MCP 派球 | 愿景仍是行首 `@` 当地址；结构化字段以后当加分项 |

## 怎么做

实现前验收应能口述：

1. 人 `@墨墨` 写完，墨墨行首 `@闪闪` → 人立刻看到接力条和「球在闪闪」，墨墨这轮的 HTTP 已结束。
2. 人去另一条线程说话，回来点继续或再发一句 → 闪闪才跑，吃的仍是那份包。
3. `@人` 仍立即停，不进 pending。
4. 有 diff 的自动审查：可标成「待审 pending」，规则与现审批卡兼容，不另做 SOP。

TDD：先写「交棒后本轮不再调用下一只 `runTurn`」的失败测试，再加 pending。

## 不做什么（本篇范围）

- mailbox 跨线程投递、猫私聊
- MCP `targetCats`、`hold_ball`
- 飞书 / 语音 / Mission Hub / SOP 五件套
- 读对方 CLI session

## 面试能讲

- **30 秒（现状）**：现在是一场接力，一条消息里跑完。图和 clowder 一样，机器更短，为了演示和审批卡同时出现。
- **30 秒（若做成）**：交棒变成「寄信 + 球标在下一只」。人能离开。入口还是 `executeTurn`，不是第二套操作系统。
- **追问「为什么现在没有」**：先把同步纪律（行首 `@`、包、隔离、人确认证据）做硬。异步是调度，不是另一套协作语义。
- **追问「和消息队列有何不同」**：队列是实现。产品上人看见的是球权，不是 topic。我们不会把 Kafka 当故事。
