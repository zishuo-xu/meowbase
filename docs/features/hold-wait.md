## 门（各一句）

- **功能**：猫行首写 `等 测试跑完`，顶栏「球在等」，人不捡球。语法见 [AGENTS.md](../../AGENTS.md) 协议表
- **价值**：等 CI / 等人补材料时，人不用当路由器
- **愿景**：邮差记持球，不替猫等外部系统
- **落点**：`parseHoldExit` + `executeTurn` 停链写系统句 + `describeBall`

## 为什么

没有 hold，猫只能 `@人` 或沉默。升级把球给人；沉默被补问或写成「球还在地上」。他们对齐的是：等，也是出口。

## 怎么做

1. 行首 `等` / `HOLD` / `hold`，后面跟原因 → 持球。句中「等等」不算。
2. 写出持球则不补问、不掉地上。系统句：`球在等:墨墨 — 原因。人开口即取消。`
3. 顶栏认这句。人下一条消息照常进 `executeTurn`，持球自然结束。持球当轮不建审批卡。
4. 验收：有 diff 仍写 `等 测试跑完` → 只叫一次、有「球在等」、没有「球还在地上」、没有审批卡。

## 不做（本篇）

- `hold_ball` MCP、`wakeAfterMs`、外部回调
- 跨线程邮箱
- 改审查通过 / 需修改

## 面试能讲

- **30 秒**：他们 F167 三选一是 pass / hold / `@`。我们 `@` 和 pass/需修改已经有了；hold 做成行首锚，平台只记账。
- **追问「和 @人 有何不同」**：`@人` 是升级拍板，球回人；`等` 是猫还持球，等人或外部条件，人开口再走。
- **为什么不抄 MCP**：邮差不替猫调外部定时器。简历讲的是球权语义，不是工具清单。
