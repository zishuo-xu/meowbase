# 同一线程同一时刻只跑一跳

- 状态:`已落地`
- 对照 clowder:他们的 ADR-018 在执行层留了一道 **thread 级 busy gate**（`tryStartThread()`，「同一 thread 不会并发两个 invocation」）。而 LL-085 记了他们真撞过的坑:**同一棵工作树共享同一个 git index**，平行 invocation 在同树里裸 `git commit` 会把别的猫 `git add` 过的文件一起卷走，作者落对了但 subject 张冠李戴。他们给的对策是**纪律**（commit 精确到文件），不是平台自动隔离;ADR-008 D5 里任务级 worktree 因为「生命周期、并发、磁盘」被暂缓。
- 靠拢:靠 ADR-018 那道 thread 级闸——**一条线程同一时刻只跑一跳**。不靠 LL-085 的纪律路线:我们的猫跑在 `bypassPermissions` 下，纪律写在系统提示里管不住，只能由平台这一侧硬来（同踩坑第 4 条的思路）。也不做每猫一棵 worktree，理由和他们 ADR-008 D5 一样，外加我们连「两棵树的产出怎么并成一张审批卡」都还没想清。

## 门（各一句）

- **功能**:同题多 `@` 仍然把同一正文发给每只点到的猫，但**一只跑完再跑下一只**;人看到的先后变确定。
- **价值**:两只猫不再在同一棵树上同时写文件、同时跑 git;改动不再张冠李戴;两条接力链不再互相盖掉对方那一棒。
- **愿景**:仍是邮差。平台只决定「谁先谁后」，不决定内容。
- **落点**:`execute-turn.ts` 里那个 `Promise.allSettled`，和它下面选 `lastResult` 的那几行。不新开第二心脏。

## 为什么

`同题并行` 是协议表里明写、对外宣传的能力，但它**没有任何保护**。已验证三条:

1. **共享工作树、共享 index。** 并行目标各跑各的接力链，但每一跳用的都是同一个 `thread.workdir`，git 操作没有互斥。这正是 LL-085 那个坑——区别是他们**整个 Project 共享 cwd**，我们已经是**每线程一棵 worktree**（`git worktree` 给每棵树自己的 index），所以我们在跨线程那一层本来就比他们隔离得好。**洞只在一条线程内部。**
2. **改动会记错人。** 每跳靠比对前后 git 快照判断谁动了什么。A 提交的时候 B 那一跳正在飞，B 的 after 快照就把 A 的提交算到 B 头上，`git-move` 落错猫。
3. **另一只的结果被直接丢掉。** 现在的代码取 `targetResults.find(r => r.status === 'fulfilled')`——**第一个**成功的，却把它命名为 `lastResult`，然后只拿它去 `settleTurn`。所以 diff、审批卡、pendingHop 全都只认一只猫的结果。两条链都交棒时，两次 `setPendingHop` 写同一条线程，**后写的盖掉先写的，一个球凭空消失**。

只在路由层有测试（唯一那条并行测试断言「每个目标收到同一条消息」），没碰文件、没碰 git、没碰 diff。所以上面三条一条都不会被现有测试发现。

## 怎么做

1. `Promise.allSettled(...)` 改成顺序循环。**保留失败隔离**:一只炸了，后面的照跑（现在这条语义是对的，别在改并发时弄丢）。
2. `lastResult` 改成名副其实的「最后一个成功的」。现在这个名字是假的，读代码的人会以为已经按顺序取了。
3. **一条线程只有一个 `pendingHop` 槽，顺序化不会自动解决它。** 先跑完那只交了棒，后跑完那只也交棒，仍然会盖掉——只是从「并发抢写」变成「顺序覆盖」，球照样丢。这一刀**不扩数据模型**（一条线程跟两棒是另一件事）:**第一个交棒的留住球**，后一个交棒的落一条 `notice` 说清「这条线程一次只跟一棒，你这一棒得人来接」。不静默覆盖，也不假装两棒都跟上了。
4. 协议表把措辞改准:「同题并行」→ 同题**群发、顺序执行**;顺带写明多 `@` 时只跟第一个交出来的棒。`AGENTS.md` 是唯一写全的地方，README / DEMO 只引用不复述。
5. 测试四条，都要能独立失败:
   - 顺序:两个目标，断言第二只**开始**时第一只已经**结束**（不是只断言两只都被调过——那条现在就能过）。
   - 失败隔离:第一只抛错，第二只仍跑完。
   - 丢球:两个目标都交棒，断言 `pendingHop` 是第一个那棒，并且有一条 `notice` 点名第二棒没人跟。
   - 归属:绑仓线程两个目标各写各的文件、各自提交，断言两个 commit 的 subject 各自对得上，没有互相卷。
6. 记分板加一行:「**两只猫同时改同一棵树**」。这是新的一道关，按踩坑第 27 条，同一轮就要加上能单独量它的那一行。它不依赖机器语言，CI 里量得准。
7. `docs/PROGRESS.md` 的厚薄表把「协议编排 厚」改成「中」，并在增量里记一句为什么——并行是协议表里明写的能力，它没保护，那条道就不能算厚。

## 不做（本篇）

- **不做每猫一棵 worktree。** 两棵树的产出怎么并成一张审批卡、冲突了算谁的，都没想清。他们 ADR-008 D5 也是因为这个暂缓的。
- **不搬 InvocationQueue。** `AGENTS.md` 明说不拿他们的实现原样;而且我们要的只是「一条线程一次一跳」，不需要一个跨线程的统一队列。
- **不碰跨线程并发。** 不同线程是不同 worktree、各有自己的 index，本来就隔离。真要做「同一个真仓库上两条线程同时干活」是另一篇。
