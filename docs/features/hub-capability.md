# Hub 能力表

一篇只写**一个**可验收的特性。写完就做这一刀，做完再开下一篇。不要在这里预写路线图。

开篇先想：同一问题他们公开怎么设计，这一刀能靠多近。能靠就靠；本刀没更近，写清差在哪、为什么先薄。不读、不抄源码。

- 状态:`已落地`
- 对照 clowder:公开 Hub Capability — 谁会干什么、什么工具、上下文预算。
- 靠拢:本刀只读名册：角色、擅长、CLI。不新开路由，不做 token 预算。

## 门（各一句）

- **功能**：Hub 里能一眼看到墨墨写、闪闪审、团团跑
- **价值**：面试和演示不用翻配置文件
- **愿景**：邮差把名册摊开给人看
- **落点**：`TeamHub` 能力页，数据来自现有 `/api/config` agents

## 为什么

没有这一页，身份只活在 system prompt 里，人看不见平台有没有纪律。

## 怎么做

1. Hub 侧栏加「能力」。
2. 列出每只猫：名字、角色、擅长、CLI。
3. 验收：打开 Hub → 能力 → 看见「主架构师」「审查官」「执行者」。

## 不做（本篇）

- Quota Board / token 预算（已花多少后来由 [quota-board.md](quota-board.md) 做了；预算和准入仍没做）
- 按能力自动改路由
- 暴露 `handoffTo` 编辑

## 面试能讲

- **30 秒**：他们 Hub 有 Capability。我们用同一页讲身份：三只猫、三种职责，路由仍在 `executeTurn`。
- **追问「和 ChatGPT 自定义人设有何不同」**：人设写进名册，交接和审查读名册，不是聊天气泡里的口头约定。
