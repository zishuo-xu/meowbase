# 排队改序与急件置顶

一篇只写**一个**可验收的特性。写完就做这一篇,做完再开下一篇。不要在这里预写路线图。

开篇先想:同一问题他们公开怎么设计,这一篇能靠多近。能靠就靠;本篇没更近,写清差在哪、为什么先薄。不读、不抄源码。

- 状态:`已落地`
- 对照 clowder:F039 / F175 —— 队里可以改序;urgent 仍在队里置顶,不旁路打断正在跑的那一跳。
- 靠拢:拿「人能把某一条挪到任意位置,急件入队就顶到队头」。差在跨来源统一出队:交棒队和人话队仍分开。

## 门（各一句）

- **功能**：面板能把非队头条目上移/下移;人话以 `!` / `急` 开头入队时自动到队头。正在跑的那一跳不停。
- **价值**：排错了不用拉闸;急一句能先出,面试能讲「急件还是信封,不是另开旁路」。
- **愿景**：仍是邮差。人可以改信封顺序,不能撕掉正在送的那封。
- **落点**：`moveQueueItem`;steer 接口加 `beforeId`;入队认急件前缀。

## 为什么

提到前面只能跳到队头。对照他们:改序是排序,urgent 不另开通道。喵窝差的就是任意位置和入队置顶。不做成 X:急件直接 abort 当前棒。

## 怎么做

1. `moveQueueItem(list, id, beforeId)`:把 id 挪到 beforeId 前面;beforeId 空则到队尾。找不到原样。
2. `POST /queue/steer` 可带 `beforeId`。不带则仍是提到队头。
3. 人话以 `!` 或 `急` 开头(可有空白)入队时 `urgent: true` 并插到队头。交棒队不认这个前缀。
4. 面板:非队头「上移」,非队尾「下移」。急件标「急」。
5. 验收:队里 A B C,把 C 上移到 B 前 → A C B;`!先看这个` 入队后 `shiftInbound` 先出它。

## 不做（本篇）

- 鼠标拖拽手势(键盘/按钮改序够演示)
- 两队合成一条、跨线程
- 急件 abort 当前棒

## 入口

- 纯函数:`packages/shared/src/queue-order.ts` `moveQueueItem` / `isUrgentInbound`
- 存储:`steerInbound` / `steerPendingHop` 的 `beforeId`;急件入队插队头
- 接口:`POST /api/threads/:id/queue/steer` 可带 `beforeId`
- 面板:`QueuePanel` 上移 / 下移 / 急
