# 家规写成告示牌

一篇只写**一个**可验收的特性。写完就做这一篇,做完再开下一篇。不要在这里预写路线图。

开篇先想:同一问题他们公开怎么设计,这一篇能靠多近。能靠就靠;本篇没更近,写清差在哪、为什么先薄。不读、不抄源码。

- 状态:`已落地`
- 对照 clowder:F073 —— 外化上下文和接力棒,不外包判断力。告示牌不是控制器。
- 靠拢:拿「线程上有共享阶段 + 一句恢复说明,猫每跳能读到,人在顶栏能看见」。不做阶段机、不做强制 MCP 写阶段。

## 门（各一句）

- **功能**：每条线程有一张家规告示牌:现在处在哪一阶段、球在谁手里、一句人能读的恢复说明。猫每跳能读到;人在顶栏能看见。
- **价值**：压缩或换会话后不必把家规再打一遍;面试能指着牌子讲「猫读的就是人看见的」。
- **愿景**：仍是邮差。牌子只写现在送到哪一站,不替猫决定下一站。
- **落点**：`Thread.sop`;平台按球权派生阶段;提示词加一段;顶栏一行。

## 为什么

家规现在写在 AGENTS.md 和每跳拼出来的纪律里,人看不见「这条线程走到哪」。对照他们:共享阶段是告示牌。喵窝差的是物化。不做成 X:简历讲流程时屏幕上只有气泡。

阶段由平台从已有事实派生,不让猫自己改——否则牌子会和球权打架。

## 怎么做

1. 阶段枚举:`idle` / `doing` / `reviewing` / `waiting` / `human`。纯函数 `deriveSopBoard(thread, messages)` 只读球权和持球,不另开状态机。
2. `Thread.sop?: { stage, holder?, note }`。每跳 settle / 入队 / 拉闸后写入。老线程没有 = 打开时现算。
3. `formatSopBoardPrompt(board)` 塞进 system prompt,标明「告示不是命令」。
4. 顶栏球权行下面一行很淡的阶段 + 恢复说明。空闲不占版面。
5. 验收:人发任务后牌子是 doing;交棒审查后 reviewing;审查通过后 human;持球 waiting。提示词含同一段 note。

## 不做（本篇）

- 强制阶段机 / 每步必须调工具改阶段
- 压缩后自动恢复 CLI session(已有捡棒)
- 人在 Hub 手改阶段

- 提示词:`buildSystemPrompt` 的 `sop`
- 顶栏:`packages/web/app/page.tsx` 告示牌一行
